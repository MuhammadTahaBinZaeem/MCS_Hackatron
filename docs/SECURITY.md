# Security and privacy — mandatory

## Identity
Student email OTP using configured approved domains (no guessed domain). Normalize according to institutional canonical identity policy; do not strip aliases without verified policy. Six digits from secrets, 5 min TTL, <=5 tries, resend >=60s, rate-limit by protected token and local request context. Store keyed OTP digest, not plaintext, transient challenge only; send email then discard raw address, do not log or expose it. HMAC-SHA256 with separate persistent local secret for canonical email uniqueness; unique token -> random private account ID mapping, atomically consume OTP and create or login existing user. Never use raw email/hash as public ID. Session random token stored hashed, expiry, rotate on login/switch, revoke logout/reset. HttpOnly SameSite cookie; loopback HTTP dev exception to Secure; origin/CSRF protection on mutation. Do not expose server outside localhost. One canonical email per student is an assumption; this is pseudonymity, not unlinkability against operator with DB+secret. Staff/admin use local seeded accounts/demo access; do not let student select role. Real email integration optional, demo uses explicitly synthetic accounts, no false real verification claims.

## Access matrix (server enforced)
| Resource | Student | Staff | Admin | Confidential handler |
|---|---|---|---|---|
| Public sanitized board | yes | safe public data only | yes | yes |
| Submit / active vote | verified only | no | no | no |
| Own history/own trust | own | no | no | no |
| Manage ordinary queues | no | own dept only | all | only if separate role |
| Own private evidence | owner | assigned ordinary case only | authorized ordinary case | assigned restricted case |
| Confidential content | own case only | no | no absent explicit permission | assigned/authorized |
| Reporter/voter real identity or internal ID | no | no | no | no |
| Adjudicate | no | no | ordinary | authorized confidential |

Never return raw ORM objects; use allowlisted public, own, staff, admin and confidential DTOs. Public issue ID is opaque, not author-linked. Private association for own reports/eligibility/ledger only. Avoid identity leakage through URLs, filenames, content, search, analytics, history, logs, notifications and admin exports; redact names/IDs/emails and withhold uncertain descriptions. No sensitive raw text to external AI. Sensitive abuse/harassment quarantine before any remote call; unknown privacy state fails closed. Backend cannot guarantee all novel sensitive language is detectable; default to review in ambiguity. No real restricted campus evidence in demo.

## Attachments
Allowed JPG/JPEG/PNG/WebP/PDF <=10 MiB each; TXT <=1 MiB; <=5 attachments and <=25 MiB per complaint. Validate bounded streamed bytes, actual signature/MIME/decoder, filename extension, reject mismatch/corruption, executables/archives/SVG/HTML, path traversal, oversized images/decompression bombs, PDF encrypted/unsupported or excessive pages (max 20) and extraction timeout. Random storage ID, private root outside static directory, permissions owner-only; never use user filename as path. Strip image EXIF/metadata by decode and re-encode; use safe derived image, retain original only privately if necessary. PDF text extracted safely, no original inline PDF public; plain text escaped, sanitized public representation only after manual review. Malware scan if configured, otherwise never claim clean; suspicious/prohibited content reject/quarantine. Keep staged uploads private, owner-bound, expiring (24h), cleanup abandoned files; failed DB/file writes compensated; reset removes demo files only.

Each attachment: purpose MAIN_COMPLAINT or SUPPORTING_EVIDENCE; ask faces FIRST, NSFW/graphic second, personal/restricted content third (YES/NO/UNSURE). Public request explicit, default private. External AI consent separate and off by default. Visibility states QUARANTINED, PRIVATE, PENDING_REVIEW, PUBLIC_APPROVED, REJECTED. A face declared/detected or uncertain, NSFW, personal/restricted, confidential issue, unavailable screening, unknown/moderation pending or no explicit consent => not public. No auto-blur publication. Local YuNet/OpenCV face detection if configured; no face identification. Detector false negatives possible, manual review of every public candidate including face/NSFW/PII/restricted checklist. Manual review may resolve uncertainty only with actual inspection; explicit YES face remains never public. Public serves sanitized derivative only; staff assigned private ordinary evidence; faces/graphic evidence restricted to authorized reviewer/handler, owner access; confidential only owner+handler. Unsafe/unvalidated file contents not served until reviewed, owner sees status. Revocation checked each retrieval; Cache-Control no-store, nosniff, content disposition safe. No guessable public URLs, cross-user attachments or orphan reuse. Public summaries must exclude sensitive details even from approved images.

## External calls
Only sanitized text/approved non-sensitive image with consent; no confidential/uncertain/restricted material, face images, identity tokens or raw email. API keys in ignored local .env, no logs, no frontend. Provider receives data not commands, no tools/SQL. Review model output using schema and deterministic rules. Network disabled or error -> clarification or review; do not silently publish.

## Demo isolation
Loopback-only synthetic mode flag + separate demo database/runtime root; switch user/passwordless create/reset/clock advance/failure simulation only in demo mode, local operator session/capability, verify origin. Rotate session on switch, clear frontend cache. Reset exclusive lock, delete/reseed demo DB contents, files, OTP, sessions, moderation, metrics, clock, invalidate pending requests; reissue demo operator session. Never delete arbitrary filesystem path or real data. Audit safe events, no secrets or PII. Do not put real data in public GitHub.
