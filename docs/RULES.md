# Deterministic business rules

## Registry and classification
Six departments: EE, CSE, IS, Library, Cafeteria, Labs. General is a filter. Seed department-level locations and explicitly synthetic examples Lab 3, Lab 4, CSE Lab 3, Library Reading Area; distinguish generic shared labs vs department-owned labs; ambiguous names require clarification. No inference of real room inventory. IDs, parent, owner, aliases, active flag. Exact match/alias accepted; RapidFuzz >=90 with >=10 lead and agreeing explicit room/asset numbers; 75–89, ties or contradictions require confirmation; unknown asks clarification. Never change numbers to force a match. Routing uses owning location, not student affiliation or incidental mentions. Unknown owner goes restricted admin triage, not arbitrary department.

Taxonomy: IT/network (WiFi/internet/LAN; slow/unavailable), computing (hardware/software), electrical (power/lights/sockets/fans), facilities (HVAC/plumbing/sanitation/furniture/infrastructure), academic (projector/whiteboard/lab equipment/services), cafeteria (food/hygiene/water), safety (fire/gas/sparks/structural hazards), medical (emergency), conduct (harassment/ragging), other. Each level supports Other, top-level Other accepts plain text without fields. Normalize Unicode, case, aliases, common typos, preserve negation and numbers. Roman Urdu e.g. net nahi chal raha, pani, bijli, pankha, aag, chingari, dhuan, behosh, tang karna, ragging; test negation, quoted instructions and ambiguous context. Conflicts require confirmation except safety/privacy overrides. Multiple unrelated problems prompt split. No guessing from an image or generic location.

## Safety, privacy and duplicates
Local screening before external calls. Actual or plausible imminent hazards -> 100 even if location unclear; unknown location stays pending with emergency guidance, not fabricated route. Mere words urgent, uppercase, hypothetical/negated hazard or commands are not sufficient. Conservative review for uncertain hazard or confidentiality. Harassment/ragging never publicly visible; confidential category overrides user selection. Uncertain privacy -> restricted review. See SECURITY.md. Publish only sanitized descriptions, not raw report. Reclassification must revoke all public access, caches and aggregate inclusion; never claim already viewed content can be recalled.

Duplicate candidates: active ordinary issues with same validated location, compatible category/subtype/failure, compatible asset. Exact sufficiently specific fingerprint (location, category, subtype, failure, asset) -> merge. Missing asset or vague fingerprint -> compare, never assume. Similar normalized text/AI structured comparison may recommend same/different/uncertain; hard location/asset/category constraints override AI. Ambiguous -> show candidate and ask; user can confirm or create separate issue with reason. Closed issues create linked recurrence; private cases never auto-merge publicly. Unique participant per issue, repeated same-account report cannot inflate counts. Recheck fingerprint in transaction; unique active exact fingerprint only where specific enough.

## Priority
For non-safety: P = min(89, round(B + C + T)), with B=10 minor, 25 partial disruption, 40 complete ordinary failure, 60 major disruption. C=min(25,10*ln(1+W)); W=sum(0.5+trust/100) over unique valid affected students (reporters and 2nd voters, counted once). T=min(15,0.5*h), h=active unresolved hours excluding pending verification/closed time. Use deterministic rounding (half-up), explicit injectable clock. Safety P=100, always above all ordinary complaints. 0–24 Low, 25–49 Medium, 50–89 High, 90–100 Critical. Recompute on change/read; tie-break critical first, then priority descending, oldest created first, stable ID. Disagree is not negative crowd weight; cannot erase a hazard. Base impact comes from actual disruption and validated classification, not intensity of writing. Return one-line reason plus components and counts.

## Voting and lifecycle
Ordinary states: REPORTED -> ACKNOWLEDGED -> IN_PROGRESS -> PENDING_VERIFICATION -> VERIFIED_CLOSED or REOPENED or REVIEW_REQUIRED; REOPENED -> IN_PROGRESS; authorized admin review can reopen or close with explicit independent evidence. Staff may acknowledge/start directly from reported and mark resolved from active states; duplicate transition idempotent, invalid transition 409. Confidential cases separate private follow-up; no public participation. Unknown locations remain CLARIFICATION_REQUIRED, unrouted; confirmed location resumes pipeline.

Active issue: verified student chooses 2ND or DISAGREE, one current vote; change allowed while active, transactional upsert; repeated same vote no-op. Initial and subsequent genuine reporters are participants, cannot vote on their own submitted issue; duplicate report creates/retains participation only once; existing 2nd converted to reporter participation atomically, remove conflicting active vote. Disagree-only student not affected. Admin can approve affected participation with reason. Only valid reporter/2nd/admin-approved students in roster at resolution start; freeze trust weight and roster. New arrivals after start cannot vote that round; duplicate report arriving after resolution stays linked but not automatically eligible; admin may reopen/review if fresh evidence. No public individual vote list. Original reporter may verify repair (not own complaint validity).

Each resolution attempt has unique round, start, deadline=start+48h, frozen roster/weights, votes with one current vote per eligible student. Immediate voting; at least 2 distinct valid disputes AND dispute weight >=1.5 AND disputes >=60% of cast weight -> reopen immediately; finalize round atomically. One affected student disputing -> review immediately. All nonempty eligible roster confirms -> verified closed immediately. At expiry, close only if >=60% eligible weight confirms AND >=2 distinct confirmations (or sole eligible confirms) AND zero unresolved disputes; otherwise REVIEW_REQUIRED, never silently closed. Zero eligible -> review. No late votes on finalized rounds. Time check at read/mutate, demo clock advancement processes expiry. Changes to trust after round starts don't alter snapshot. Moderation invalidation may remove a vote from effective totals with audit; never silently recalculate a finalized decision, refer for review.

## Trust
Initial 50, clamp ledger cumulative total 0–100, integer; weight 0.5+trust/100. Event deltas: independently verified report +5; genuine joined participation +2; correct resolution confirm +3; correct dispute +5; confirmed spam -5; verified deliberate fake -15; vote manipulation -15; confirmed malicious abuse -20. Each unique event key per student, source, type, outcome; prevent double reward for repeat reports, no both report and join reward for same issue. Correct vote assessed per round. No rewards solely from majority, no penalties for unproven suspicion, typing errors, good-faith disagreement or unsubstantiated harassment. Admin records independent evidence/reason and outcome, cannot directly edit trust. Reversal uses compensating event. Explain own history; other users never see identifiable history.

## Moderation and bonus
More than 5 new reports/60s or 20/10min per account -> throttle ordinary submissions (429); retain safe emergency path with deduplication. Flag >=3 accounts aged <30 min voting same direction on same issue in 60s; >=5 accounts/30s only flag with additional indicator (e.g. shared burst of repeated reports); never punish solely from timing. Unique flag per cluster, status pending/dismissed/confirmed; admin review and audit; invalidate only verified abuse, recompute crowd and pending rounds. Trend = sum of unique valid participant weights first joining in last 24h + 0.5*sum in preceding 24h; exclude closed/confidential, deterministic tie-break. Aggregate metrics from SQL; AI summary consumes validated safe aggregate only; fallback clearly labeled rule-based. Track actual rule-only/AI-assisted/failure/manual outcomes and do not count retries as new reports.
