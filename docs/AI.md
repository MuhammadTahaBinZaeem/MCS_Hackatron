# AI integration and offline fallback

Rules first; GPT handles ambiguity, complex Roman Urdu and semantic arbitration. User-provided available names: gpt-5.4-nano (fast), gpt-5.4-mini (standard), gpt-5.4 (complex), gpt-5.6-luna (optional escalation). These are configuration candidates, not verified Azure deployment IDs or capability guarantees. Exact deployment/endpoint/API version and supported structured output/vision must be probed. Use OpenAI Python SDK, appropriate Azure/OpenAI-compatible adapter, optional Featherless text/vision adapter. No hardcoded key/model discovery assumptions; keys from environment. Mock only in tests, visible demo provider-disabled status. Bounded total deadline e.g. 12s, max 2 attempts across providers, circuit-break after repeated failure, no network in transactions. Use smaller model first, escalate only ambiguity/error; no automatic chain of every model. Report provider metrics; no fake AI result.

## Contracts
TextProvider.classify(input)-> ClassificationSuggestion or typed failure; compare(input,candidates)-> SAME/DIFFERENT/UNCERTAIN plus candidate ID and reason; summarize(aggregates)-> safe narrative. VisionProvider.analyze(image)-> VisionSuggestion or NOT_CONFIGURED. Inputs are untrusted data, not executable. Do not give tools, database or policy overrides. Structured response via supported JSON schema or parse+validate strictly (extra forbid); reject malformed/unknown enum, unsupported IDs, invalid ranges. Never accept a final priority or authorization from model. Example:
```json
{"department_candidate":"CSE","location_candidate":"Lab 3","category":"NETWORK","subcategory":"WIFI","failure_type":"UNAVAILABLE","asset_identifier":null,"impact":"COMPLETE_DISRUPTION","hazard":"NONE","confidentiality_suspected":false,"normalized_description":"WiFi unavailable","reason":"Network service is disrupted","clarification_required":false}
```
Backend cross-check registry, actual issue/asset/type, safety/privacy, allowed enums; handle negation, fake urgent, injection, contradiction and unknown location. Rules can process structured complaints without LLM, Other falls back to aliases and clarification. Safety detection remains mandatory even in guided form. Confidential/ambiguous privacy locally quarantine, never external AI. Do not use model confidence as sole decision. For summary supply only sanitized aggregate counts and safe descriptions, label output AI or conventional fallback; verify numeric claims against aggregates or omit unsupported numbers.

## Vision (Stage 8 only)
Reserve disabled interface Stage 0, file metadata Stage 1, local review Stage 6. Candidate Featherless models: Qwen3-VL-8B-Instruct or Mistral Small 3.2 variants only if account API confirms model ID, multimodal support and limits; test with synthetic images. Optional configured Azure vision deployment. Input: sanitized, reviewed non-sensitive image with no faces and explicit external consent; never send confidential/uncertain material. Output typed description/category/subtype/failure/hazard_suspected/faces_detected/nsfw_suspected/personal_information_suspected/clarification_required, optional confidence. No identity recognition, no location invention, no assertion that visually intact equipment works. Local face and manual review gate independent of AI. Vision can recommend complaint type, not public clearance. If offline/unavailable, manual category/location and evidence workflow remain functional. Do not label unavailable live integration PASS; note actual test evidence and manual fallback.
